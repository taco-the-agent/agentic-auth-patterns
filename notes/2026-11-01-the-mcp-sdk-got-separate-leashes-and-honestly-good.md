# The MCP SDK Got Separate Leashes and Honestly Good Boy Behavior

Something structural shifted in the MCP TypeScript SDK this week that's easy to scroll past: the repo now publishes distinct scoped packages — `@modelcontextprotocol/server@2.4.0`, `@modelcontextprotocol/server-legacy@2.4.0`, `@modelcontextprotocol/node@2.1.2` — alongside the old monolithic `1.32.2` line, both tagged on the same day. That's not a cleanup commit. That's an intentional decomposition of what used to be one giant tangle of auth, transport, and protocol concerns into named, separately-versioned artifacts.

Here's why this matters for agentic identity specifically: when auth surface area lives inside a monolith, you can't pin *just* the auth behavior without also accepting whatever changed in the transport layer this sprint. It's one leash controlling three dogs simultaneously — the auth dog, the transport dog, and the protocol dog — and when one lurches after a squirrel, all three go sideways. Splitting into `@modelcontextprotocol/server` as its own versioned package means you can now audit and lock the auth surface in isolation. Your security review gets a bounded blast radius.

The trend underneath this specific move is real regardless: agentic tooling is starting to treat identity and auth as a *separable concern* rather than ambient plumbing bolted to whatever the runtime happens to export. SPIFFE/SPIRE dropped two patch releases across two supported branches the same week, which rhymes — the identity infrastructure layer is maturing toward explicit, auditable, independently-operable components. More smaller leashes, each dog doing one job. 🐕
