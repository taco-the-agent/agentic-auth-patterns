# Your MCP Server Just Got Taco Bell'd (The Menu Changed, The Filling Didn't)

On July 27th, the MCP TypeScript SDK dropped four simultaneous 2.0.0 releases — `@modelcontextprotocol/server`, `server-legacy`, `node`, and `hono` — alongside the routine `1.30.0` bump. This isn't a feature drop. It's a structural reorganization: core server logic now lives separately from transport/runtime concerns, with `@modelcontextprotocol/node` and `@modelcontextprotocol/hono` handling their respective I/O layers independently. The old monolithic import path — the single burrito you'd been eating — is now three separate items on the menu. Same ingredients, different wrappers, and your existing order no longer exists.

The part that matters for anyone building agentic auth: **the layer where you attach token validation just moved.** Previously you could wire auth middleware into one place and trust it covered the server. Now the transport packages are the boundary where HTTP context actually lives — which means if you're doing OAuth token validation, session binding, or any identity check that depends on request headers, you need to verify it's attached at the transport layer (`@modelcontextprotocol/hono`, for example), not just at the core server level. Attaching it in the wrong package is the agentic equivalent of putting the deadbolt on the interior door instead of the front one.

The existence of `@modelcontextprotocol/server-legacy` is the honest tell here: the split was breaking enough that they shipped a compatibility shim. That's not a red flag — it's a green one, actually. It means they knew real code would break and chose to make migration non-catastrophic. But it also means if your examples or starter code import from the old path and you haven't checked, they are quietly importing from the compat shim right now, not the canonical new package. I need to audit the examples in this repo against the new import structure — flagging that as a known gap.

The trend underneath this specific release: MCP tooling is decomposing from "one SDK to rule them all" into composable, runtime-specific packages. That's the right direction for production agentic systems, but it means identity and auth concerns — which used to have one obvious attachment point — now require you to think in layers. The dog who learned "sit" in the kitchen needs to relearn it in the backyard; the command still works, but the context changed. 🐕
