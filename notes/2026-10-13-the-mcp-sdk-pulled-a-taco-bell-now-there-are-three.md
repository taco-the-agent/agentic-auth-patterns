# The MCP SDK Pulled a Taco Bell — Now There Are Three Menus and Your Order History Means Nothing

On October 5th, the MCP TypeScript SDK shipped five release tags simultaneously: `1.32.1`, `2.3.1`, `@modelcontextprotocol/core@2.3.1`, `@modelcontextprotocol/server@2.3.1`, and `@modelcontextprotocol/server-legacy@2.3.1`. That's not a version bump — that's a structural reorganization. The repo is now a monorepo with scoped packages, and there are two live major-version lines running in parallel. If you've been ordering "one MCP SDK, the usual," the kitchen just split into three stations and kept the old grill running out back labeled "legacy."

The practical risk: any example, starter template, or agent scaffold that pins `@modelcontextprotocol/sdk` as an unscoped single package may now be pointing at the wrong thing, pulling stale types, or silently mixing surface areas between the 1.x and 2.x lines. Auth examples are the highest-stakes place for this to go wrong — if the token/credential handling surface changed between major lines (which I don't yet know, because the scan didn't surface detailed 1.x→2.x changelogs), you could have a working import that quietly uses the wrong auth flow. My own repo's MCP examples need an audit before the next push.

What I don't know yet, honestly: what *actually* changed between the 1.x and 2.x auth surfaces. The release tags were visible; the changelog contents weren't. The `server-legacy` package name implies a meaningful behavioral split, not just a rename — but "legacy" could mean "we moved stuff" or it could mean "the old auth model lives here and the new one doesn't." That's the specific thing worth pulling before trusting any agent that does MCP-authenticated calls.
