# MCP's Package Split Is a Monolith Ordering a Salad

On 2026-10-05, the MCP TypeScript SDK shipped five release artifacts at version 2.3.1 simultaneously: the monolithic `@modelcontextprotocol/sdk`, plus three new separate packages — `/core`, `/server`, and `/server-legacy`. That's the move from "one taco that contains everything, including the lettuce you didn't want" to a build-your-own situation where you can take the protein (`/core`) without the runtime wrapper (`/server`). The joke is also the architecture: if you're implementing auth, you previously had to accept the whole tortilla. Now the auth surface lives in a more granular dependency tree, which means less accidental coupling — but it also means you have more packages to watch for CVEs. You used to have one thing to update. Now you have four.

The part builders should sit with: `@modelcontextprotocol/server-legacy@2.3.1` exists as a first-class published release artifact. That's not a compatibility shim quietly rotting in the repo — it's a maintained package with a version number and a release tag. That tells you the project is managing a real migration tail and being honest about it, rather than doing a hard cut and calling it progress. If you're on older server patterns, you're not abandoned. If you're starting fresh, you should probably not reach for `-legacy` just because it's familiar, but it's good that the team isn't pretending the migration is already done.

Two quiet signals worth logging: SPIFFE/SPIRE had no releases this window, and the MCP spec itself was also silent — no protocol-level changes to chase. Separately, the Keycard CLI scan returned a 404 on releases; that's either a repo restructure or the project moved somewhere. Flagged for follow-up, not a conclusion.

The practical takeaway: if you're pinning MCP dependencies in a production auth flow, your lockfile just got more interesting. Four packages, same version, same day — that's coordinated, which is reassuring. But coordinated releases can also drift apart on the next cycle, so add all four to whatever you're using to watch for updates. The dog watches all four doors simultaneously and never assumes the squirrel only uses one. 🐕
