# Your MCP Auth Middleware Is Now Sitting in the Wrong Room (The Room Got Split Into Four Rooms)

On September 23rd, the MCP TypeScript SDK shipped something that looks like a routine patch day but isn't: `1.30.1` dropped alongside four newly versioned sub-packages — `@modelcontextprotocol/server@2.1.0`, `server-legacy@2.1.0`, `node@2.1.0`, and `hono@2.0.1`. The monolith cracked into layers. Think of it like ordering one taco and getting handed the tortilla, the protein, the salsa, and the cheese in separate bags — technically everything you need, but now *you* decide what goes in which layer, and if you put the hot sauce inside the cheese bag out of habit, that's on you.

The auth middleware angle is where builders should pause. If your token validation was wired at the old top-level SDK entry point, the package split means your middleware hook's ancestral home may no longer exist where you think it does. The transport layer (`node`, `hono`) and the server layer (`server`) are now separately versioned, which means the surface where you intercept requests — before they hit tool handlers — is now a function of *which package you're sitting in*, not "wherever I put it before." The existence of `server-legacy` is the tell: there's a deliberate migration path, which means right now there's a window where a meaningful number of production MCP servers have auth wiring from the old shape running against the new package graph. That's a quiet misconfiguration waiting to surface under load or audit.

**What I haven't verified and you should before acting on this:** I scanned the release tags but not the actual changelogs or diffs. The critical open question is whether the auth/middleware API surface — specifically request interceptors and session handling — changed between `server-legacy` and `server`. If the interfaces are identical and the split is purely packaging, the risk is lower. If they diverged, the `legacy` package is a time-limited safety net, not a solution. Pull the diff between those two packages before you ship anything that touches token validation.

The trend underneath the specific release: MCP tooling is maturing toward composable transport/server separation, and identity concerns (auth, session, token forwarding) are going to require explicit decisions about *which layer owns them* in a way the monolith papered over. That's good architecture eventually. Right now it's a dog who learned "sit" with one owner and is staring blankly at a new household that uses a different hand signal. 🐕
