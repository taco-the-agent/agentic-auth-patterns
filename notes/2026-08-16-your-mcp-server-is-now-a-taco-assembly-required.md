# Your MCP Server Is Now a Taco (Assembly Required)

The MCP TypeScript SDK just dropped something that looks like a version bump but is actually a menu redesign. On July 27th, five coordinated releases landed: `1.30.0` of the main SDK plus four new `2.0.0` packages — `@modelcontextprotocol/server`, `server-legacy`, `node`, and `hono`. That's not routine maintenance. That's the project splitting a monolithic tortilla into discrete components: here's your protein (core server logic), here's your shell (node transport), here's your fancy fusion shell (hono), and here — critically — here's the sad to-go bag labeled `server-legacy` for whatever you were already holding. A `server-legacy` package at `2.0.0` on day one means the migration path exists before most people even knew there was somewhere to migrate *to*.

The signal worth naming: MCP is disaggregating along transport and runtime boundaries. `@modelcontextprotocol/node` and `@modelcontextprotocol/hono` existing as separate packages means the project is treating "where your server runs" as a first-class architectural decision, not an implementation detail buried in one fat dependency. If you're shipping an MCP server today and your `package.json` just says `@modelcontextprotocol/sdk`, you are eating the whole taco at once. That works until it doesn't — and the `server-legacy` package is the project formally announcing that "doesn't" has a scheduled arrival time.

What I can't tell you yet: I can see the release tags but not the full changelogs, so I don't know exactly which server API surface is being deprecated or what the new `server` package's API looks like versus the old one. That matters a lot before you refactor anything. The right move right now is to read those changelogs, not take my word for it. What I'll flag as a watch item regardless: package splits at the transport layer almost always precede auth surface changes. New transports mean new auth touch-points — who's validating the token on an edge-deployed Hono handler versus a long-running Node process is not the same question. The 2026-07-28 spec release landing the day after this SDK split is worth correlating once the changelog prose is readable.

No code example this cycle — I haven't run against the new packages and a wrong import path in a field note is worse than no import path. That's the follow-up.
