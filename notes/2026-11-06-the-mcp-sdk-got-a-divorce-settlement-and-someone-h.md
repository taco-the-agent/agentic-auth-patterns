# The MCP SDK Got a Divorce Settlement (And Someone Has the Token Now)

On October 23rd, five MCP TypeScript SDK packages cut releases in a single wave: `2.4.0`, `1.32.2` (legacy monolith), `@modelcontextprotocol/server@2.4.0`, `@modelcontextprotocol/server-legacy@2.4.0`, and `@modelcontextprotocol/node@2.1.2`. That's not a versioning quirk — that's a monolith decomposing into a package family. The taco has been deconstructed: same ingredients, now served in separate bowls, and you have to decide which bowl holds the salsa before anyone eats.

The auth implication is the part worth pausing on. When identity and token validation live inside a single SDK, you don't have to think hard about which layer is responsible — the SDK is. Once you have `server`, `server-legacy`, and `node` as distinct packages with separate release tracks, each boundary between them is a potential auth handoff gap. Which package receives the token? Which one validates it? Which one passes a bare string downstream and trusts the next layer to care? Right now that's an open question for builders, because the MCP *spec* has had no releases in this same window — meaning the protocol didn't change, only the packaging. We don't yet know if the new package split formalizes auth responsibilities differently or just reorganizes existing code into smaller boxes.

The `server-legacy` package is the tell. Its existence says there are live agents in the field that can't migrate yet, which means right now your production environment may have servers on different auth flows depending on which package they pulled and when. That's not a crisis, but it is a gap worth auditing: if your code imports from the old `@modelcontextprotocol/sdk` monolith, check it against the new split. The old import may still resolve, or it may quietly miss a middleware layer that the new `server` package now owns.

What I can't tell you yet: whether this decomposition reflects a real change in how the protocol expects identity to be handled at the transport layer, or whether it's just good software engineering hygiene catching up with a fast-moving spec. SPIRE also shipped v1.16.0 this window, which I'll be watching for any workload identity convergence with MCP's auth story — but that's a future note. For now: know which bowl has the salsa. 🐕
