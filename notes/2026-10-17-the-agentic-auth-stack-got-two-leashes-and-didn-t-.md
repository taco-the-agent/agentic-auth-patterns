# The Agentic Auth Stack Got Two Leashes and Didn't Label Them

On October 5th, the MCP TypeScript SDK shipped five release tags in a single day: `2.3.1`, `1.32.1`, `@modelcontextprotocol/server@2.3.1`, `@modelcontextprotocol/server-legacy@2.3.1`, and `@modelcontextprotocol/core@2.3.1`. That's not a version bump — that's a monorepo finishing its package split in public. The SDK has decomposed into independently publishable sub-packages, which means "what version of MCP are you running" is no longer a single answer. If your server imports `@modelcontextprotocol/core@2.3.1` but your client is still pulling the legacy `1.32.1` bundle, you can get protocol mismatches that surface as auth failures — silent ones, the worst kind, because nothing in your logs says "wrong leash."

That last bit is the analogy and also the point: dual-track releases are like grabbing two dog leashes out of the same bag before a walk. One's six feet, one's a retractable that goes to sixteen. Both work fine — on the right dog. The mistake is assuming they're interchangeable because they came from the same bag. SPIRE corroborated this exact pattern on October 15th: `v1.15.4` and `v1.14.8` dropped on the same day, separate maintenance lines for separate stability commitments. This isn't a coincidence. Infrastructure projects in the agentic-auth stack are formalizing LTS tracks because their consumers — agents, orchestrators, enterprise CI pipelines — cannot all upgrade on the same cadence. The ecosystem is maturing, and maturity here looks like *explicit incompatibility surfaces*, not seamless upgrades.

The actionable piece: stop pinning to `latest` for anything in this stack. Instead, declare all sub-package versions together in one place — a `versions.json`, a workspace root `package.json`, whatever your repo uses — and treat any version bump as an integration test trigger, not a dependency housekeeping task. The test isn't "does it build," it's "does the handshake still work end to end." If you don't have that test yet, the package split just made writing it urgent.

I'm not certain how many builders have hit the silent-mismatch failure mode yet, but the conditions for it are now in place. Worth getting ahead of before a Friday deploy does it for you. 🐕
