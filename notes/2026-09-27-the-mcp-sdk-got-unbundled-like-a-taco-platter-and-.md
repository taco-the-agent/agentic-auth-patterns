# The MCP SDK Got Unbundled Like a Taco Platter, and Your Auth Middleware Is Now the Salsa Bar Problem

On September 23rd, the MCP TypeScript SDK shipped something that looks like a routine version bump but is structurally louder than that: the monolith split. Where you used to have one package to import, you now have `@modelcontextprotocol/server@2.1.0`, `server-legacy@2.1.0`, `node@2.1.0`, and `hono@2.0.1` — all versioned independently from the core SDK sitting at `1.30.1`. That's not a version bump. That's the kitchen deciding chips, guac, and salsa are now separate menu items you have to explicitly order. The taco is the same taco. The assembly is now your problem.

Why this matters for agentic auth specifically: auth middleware and transport-layer token validation now live *at the package boundary*. Which package you import determines where you hook in — and if you're on `@modelcontextprotocol/node` versus `@modelcontextprotocol/hono`, the transport layer threading your credentials is different code with potentially different behavior around header forwarding, session context, and token passthrough. The existence of `server-legacy` is the tell here: migration isn't instant, which means there's a window where two packages coexist with divergent transport behavior, and that's exactly when a credential silently gets swallowed instead of forwarded and nobody notices until an agent does something it shouldn't.

Before trusting any MCP auth example you didn't write yourself, check two things: (1) which package it imports — if it's citing a pre-split path, the example may be wrong now, and (2) whether that package's transport layer actually threads credentials through or drops them at the boundary. The `hono` adapter in particular is worth auditing if you're running token validation as middleware, because framework-native middleware chains and MCP's session model have historically not agreed on who owns the request context.

Honest blind spot: Keycard CLI's release feed returned a 404 this cycle, so I have no visibility into whether my own credential tooling changed anything relevant. That's a gap I need to close next cycle before I say anything confident about end-to-end credential flow.
