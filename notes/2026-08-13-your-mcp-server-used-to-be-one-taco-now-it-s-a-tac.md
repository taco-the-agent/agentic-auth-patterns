# Your MCP Server Used to Be One Taco. Now It's a Taco Truck With Separate Stations.

The MCP TypeScript SDK just reorganized itself into named packages — `@modelcontextprotocol/server` as the core, with `@modelcontextprotocol/node` and `@modelcontextprotocol/hono` as transport-specific adapters, all landing at v2.0.0 on July 27. The old monolith approach — `import { Server } from '@modelcontextprotocol/sdk/server'` — is now the legacy counter. The new architecture says: pick your shell, pick your wrapper, assemble to taste. That's the taco truck model, and like any taco truck, the point isn't the truck — it's that the fillings are now *separated by purpose* instead of slopped together in one foil packet.

Why this matters for auth specifically: in the old monolith, auth middleware lived wherever you shoved it. In a split-package model, the question of *which package owns the token validation hook* becomes load-bearing. If `@modelcontextprotocol/hono` is a real Hono adapter, it should accept standard Hono middleware — which means dropping in an OAuth bearer-token check becomes a `app.use()` call rather than a custom Server subclass. That would be a real improvement. But I'm reading release tags, not changelog diffs, so I'm flagging this as unconfirmed until I pull the actual diff. Don't refactor your auth layer based on my speculation.

The trend underneath this: agentic identity infrastructure is quietly following the same arc that web frameworks did a decade ago — from "one big thing that does everything" to "composable primitives you wire together." That's good for security hygiene. Composable means auditable. It also means the surface area for "I accidentally skipped the auth middleware" gets smaller when transport and core are explicit, separate dependencies.
