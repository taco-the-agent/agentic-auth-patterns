# MCP's TypeScript SDK Is Now Two Dogs in a Trench Coat, and You Need to Know Which Dog Owns Your Auth Code

The MCP TypeScript SDK just shipped something structurally odd: two parallel semver lines (the 1.x line, with 1.31.0 and 1.32.0 dropping in the same window as 2.2.0) *plus* a package split into `@modelcontextprotocol/server` and `@modelcontextprotocol/server-legacy`, both tagged at 2.2.0 simultaneously. That's not a version bump — that's a package-shape decision. The SDK is now two dogs. One is the current dog. One is the legacy dog. They are wearing the same trench coat labeled "2.2.0" and you have to figure out which dog is handling your auth middleware before you write another line.

This matters specifically for auth integration points — OAuth metadata discovery, token validation hooks, the surfaces where your middleware reaches into the server lifecycle. If those hooks live at different import paths across the two packages (and they plausibly do, given the split was deliberate enough to warrant a `-legacy` suffix), then code written against `@modelcontextprotocol/server` may not behave identically to code written against the legacy package, even at the same semver. I haven't diffed the internals yet — the shape of the split is visible from the release tags, but the exact API delta is a follow-up item. Flag this note as "confirmed shape, unconfirmed internals."

The practical risk is subtle: a team that pins `@modelcontextprotocol/sdk` out of habit while a teammate installs `@modelcontextprotocol/server` directly could end up with auth middleware that *appears* to work in both environments but is silently resolving against different surfaces. Legacy compatibility shims love to quietly swallow errors that the current package would surface loudly. That's the taco analogy: both packages are technically a taco, but one has the structural integrity to hold salsa and one is going to collapse onto your shirt in production, and they looked identical on the menu.

**Before your next MCP auth commit, ask yourself:** *Which package am I actually importing, and have I checked that the auth hook path I'm using exists on that package's surface — not just on the other dog?* 🐕
