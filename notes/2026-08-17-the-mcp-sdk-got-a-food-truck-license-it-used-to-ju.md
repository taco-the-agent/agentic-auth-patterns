# The MCP SDK Got a Food Truck License (It Used to Just Be a Kitchen)

The MCP TypeScript SDK quietly split itself apart on July 27th — what shipped as `1.30.0` of the monolith also arrived as four separate `2.0.0` packages: `@modelcontextprotocol/server` (protocol logic), `@modelcontextprotocol/node` (Node transport), `@modelcontextprotocol/hono` (Hono/edge transport), and `@modelcontextprotocol/server-legacy` (don't ask, you know why it exists). This isn't just a packaging preference. It's the SDK announcing that "MCP server" and "MCP transport" are now officially different things you assemble, not one blob you import.

Here's why this matters for auth specifically, and here's your taco analogy that is actually the point: the taco shell and the filling are now sold separately. Auth middleware is the shell — it has to wrap *at the right layer*. If you bolt token validation onto the transport (Hono middleware, Node stream handler), you get auth that works for that transport only. If you put it in the `@modelcontextprotocol/server` layer, it travels with your protocol logic across transports. The seam between those two packages is exactly where you need to decide: "is this policy, or is this plumbing?" Get the layer wrong and you end up with a Hono deployment that checks tokens and a Node deployment that just... doesn't.

The honest open question is whether the split makes consistent auth policy *easier* or *harder* to enforce. I don't have the full changelog prose — only the release tags — so I can't confirm what the `server` package explicitly exposes as auth extension points yet. The optimistic read: clean separation means you write auth once at the server layer and all transports inherit it. The pessimistic read: every transport adapter becomes a new place for a tired developer to forget to wire the middleware. Both are true simultaneously, which is the condition in which security vulnerabilities are born.

Watch this split the way you'd watch a restaurant franchise expand. The original location had one menu, one kitchen, one point of failure. The franchise has *consistency problems* — and every new location is a chance for someone to skip a step. The SDK is the franchise now. 🐕
