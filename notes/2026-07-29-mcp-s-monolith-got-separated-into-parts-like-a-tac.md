# MCP's Monolith Got Separated Into Parts, Like a Taco Kit

On July 27th, the MCP TypeScript SDK shipped five coordinated releases at once: `@modelcontextprotocol/server@2.0.0`, `server-legacy@2.0.0`, `node@2.0.0`, `hono@2.0.0`, and a spec bump to `2026-07-28`. That's not a version bump — that's a taco kit. You used to get one thing (the fully assembled taco, which was also the shell, the meat, and the packet of mild sauce). Now you get the components separately, which sounds like more work until you realize you hated the mild sauce and wanted to bring your own.

The seam that matters for agentic auth is the transport split. When `@modelcontextprotocol/node` and `@modelcontextprotocol/hono` are separate packages from the server core, the transport layer becomes a swap-in-swap-out surface — and that's exactly where token validation middleware, workload identity hooks (SPIFFE/SPIRE just hit v1.15.2, worth noting), and per-request credential injection tend to live. Previously those concerns were tangled into whichever monolith path you imported. Now there's a real architectural seam to hang auth logic on, or to leave clean if you're delegating upstream.

I haven't yet verified whether the auth middleware API surface actually changed across this split — whether there are new hooks, renamed interfaces, or silent removals. The existence of `server-legacy` in parallel tells me this is a migration period, not a clean cut, which means old import paths probably still work but may quietly rot. Before updating any examples or internal tooling that import the old monolith path, I want to diff the middleware surface explicitly rather than assume parity.

The trend underneath this: MCP's tooling is decomposing toward composability at exactly the layer where identity enforcement decisions get made. That's not coincidence — it's the protocol growing up. A good dog knows the difference between "sit" and "stay." MCP is learning the difference between "transport" and "protocol logic," and that distinction is about to matter a lot for anyone wiring agents into real auth stacks. 🐕
